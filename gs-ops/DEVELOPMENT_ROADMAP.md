**制定日期**: 2026-06-13

## 📋 执行摘要

基于项目完成情况分析，当前 gs-ops 已完成核心功能开发（~70%），具备基本可用性。本路线图规划了从当前状态到 v1.0.0 生产就绪版本的完整开发计划。

### 关键目标
1. ✅ 完善认证和权限系统
2. ✅ 实现 WebSocket 实时日志
3. ✅ 增加测试覆盖到 60%+
4. ✅ 实现批量操作和健康检查
5. ✅ 完善文档和部署方案

### 优先级原则
- **P0 (阻塞性)**: 安全和稳定性问题，必须完成
- **P1 (高优先级)**: 核心功能缺失，强烈建议完成
- **P2 (中优先级)**: 体验优化，建议完成
- **P3 (低优先级)**: 锦上添花，可延后

## Phase 1: v0.4.0 - 安全和认证 (Week 1-2)

**发布日期**: 2026-06-27  
**优先级**: P0 (阻塞性)  
**工作量**: 10-12 天

### 目标
实现完整的用户认证和权限系统，消除当前的安全隐患。

### 功能清单

#### 1. JWT 认证系统 (P0) - 3 天
**后端**:
- [ ] 安装/实现 JWT 库
  - `backend/utils/jwt.gs` - JWT 生成、验证、刷新
  - `backend/utils/hash.gs` - 密码加密（bcrypt/argon2）
- [ ] 用户数据模型
  - `backend/models/User.gs` - 用户模型
  - 数据库表: `users` (id, username, password_hash, role, created_at, updated_at)
- [ ] 认证中间件完善
  - `backend/middlewares/auth.gs` - 从占位实现改为真实 JWT 验证
  - 白名单路由: `/api/auth/login`, `/api/health`
- [ ] 登录/登出接口
  - `POST /api/auth/login` - 登录返回 JWT
  - `POST /api/auth/logout` - 登出（客户端删除 token）
  - `POST /api/auth/refresh` - 刷新 token
  - `GET /api/auth/me` - 获取当前用户信息

**前端**:
- [ ] 登录页面
  - `frontend/src/views/Login.vue` - 登录界面
  - 表单验证、错误提示、loading 状态
- [ ] Token 管理
  - `frontend/src/utils/auth.js` - token 存储、刷新逻辑
  - localStorage 存储 token
  - axios 拦截器自动添加 Authorization header
- [ ] 路由守卫
  - `frontend/src/router/index.js` - 未登录跳转到登录页
  - 登录后跳转到 dashboard

**测试**:
- [ ] 登录成功/失败测试
- [ ] Token 过期自动刷新测试
- [ ] 未授权请求拦截测试

#### 2. 权限控制系统 (P0) - 2 天
**后端**:
- [ ] 角色定义
  - 角色: `admin`, `operator`, `viewer`
  - 权限: 服务管理、配置修改、只读查看
- [ ] 权限中间件
  - `backend/middlewares/permission.gs` - 检查用户角色和权限
  - 装饰器模式: `requireRole(['admin', 'operator'])`
- [ ] 操作日志增强
  - 记录操作用户 (从 JWT 获取)
  - `operation_logs.operator` 改为真实用户名

**前端**:
- [ ] 权限指令
  - `frontend/src/directives/permission.js` - v-permission 指令
  - 根据用户角色隐藏/禁用按钮
- [ ] 用户信息展示
  - Header 显示当前用户名和角色
  - 下拉菜单: 修改密码、登出

**测试**:
- [ ] 不同角色权限测试
- [ ] 越权操作拦截测试

#### 3. 用户管理界面 (P1) - 2 天
**后端**:
- [ ] 用户管理 API
  - `GET /api/users` - 用户列表（仅 admin）
  - `POST /api/users` - 创建用户（仅 admin）
  - `PUT /api/users/:id` - 更新用户（仅 admin）
  - `DELETE /api/users/:id` - 删除用户（仅 admin）
  - `PUT /api/users/:id/password` - 修改密码（自己或 admin）

**前端**:
- [ ] 用户管理页面
  - `frontend/src/views/Users.vue` - 用户列表和管理
  - 用户列表、添加用户、编辑用户、删除用户
- [ ] 修改密码对话框
  - `frontend/src/components/user/ChangePasswordModal.vue`

**测试**:
- [ ] 用户 CRUD 操作测试
- [ ] 密码修改测试

#### 4. 安全加固 (P0) - 2 天
- [ ] **密码策略**
  - 最小长度 8 位
  - 必须包含大小写字母、数字
  - 密码历史（不能重复最近 3 次）
- [ ] **会话管理**
  - Token 有效期 24 小时
  - Refresh token 有效期 7 天
  - 同一用户多设备登录支持
- [ ] **安全审计**
  - 登录失败记录
  - 敏感操作审计日志
  - 异常登录告警（可选）
- [ ] **输入验证**
  - 所有用户输入验证
  - SQL 注入防护（ORM 已有）
  - XSS 防护

#### 5. 数据库迁移 (P0) - 1 天
- [ ] 创建 users 表
  - 迁移脚本: `backend/utils/migrate_v0.4.0.gs`
  - 默认管理员账号: admin/admin123 (首次启动)
- [ ] operation_logs 表增加字段
  - `operator_id` - 用户 ID
  - 索引: operator_id

### 验收标准
- ✅ 用户必须登录才能访问系统
- ✅ 不同角色有不同的操作权限
- ✅ 所有操作记录真实操作用户
- ✅ 密码安全存储（hash）
- ✅ Token 自动刷新
- ✅ 通过基本安全测试

### 测试计划
- [ ] 单元测试: JWT 生成/验证、权限检查
- [ ] 集成测试: 登录流程、权限控制

- 提前进行性能测试

**风险**: 60% 覆盖率可能难以达成  
**影响**: v0.6.0 延期  
**缓解措施**:
- 优先测试核心功能
- 使用测试辅助工具
- 适当调整覆盖率目标（最低 50%）

**风险**: Windows/Linux 行为差异  
**影响**: 功能在某些平台不可用  
**缓解措施**:
- 早期在多平台测试
- 使用统一的抽象层
- 准备平台特定的回退方案

- 先实现简单规则
- 复杂规则延后到 v1.1.0
- 参考开源告警系统

#### 5. 文档编写工作量 (P1)
**风险**: 文档工作量被低估  
**影响**: v0.9.0 延期  
**缓解措施**:

- 必要时引入技术写作支持

## 🔄 迭代策略

4. **渐进式交付** - 功能逐步上线，避免大爆炸

### 版本发布流程
1. **开发分支** - `feature/xxx` 开发新功能
2. **代码审查** - PR 审查通过后合并到 `develop`
3. **集成测试** - 在 `develop` 分支运行完整测试
4. **发布候选** - 合并到 `release/vX.X.X` 分支
5. **回归测试** - 完整测试发布候选版本
6. **正式发布** - 合并到 `main` 分支并打 tag
7. **发布监控** - 监控生产环境运行状态

### 回滚计划
- 每个版本保留数据库迁移回滚脚本
- 配置变更可回退
- Docker 镜像保留最近 3 个版本
- 代码仓库保留所有 tag
